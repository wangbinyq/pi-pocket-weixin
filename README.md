# pi-pocket-weixin

微信 ↔ **Pi Pocket / Pi in Pocket（PiP）** 的独立 TypeScript 桥接服务。

默认连接你现有的 PiP 管家；用命令切换到已有 Pocket 会话。复用同一个上下文、模型、工具和任务，不另起 Hermes/OpenClaw agent，也不改 Pocket 的源码或数据库。

> **0.1 原型：** 已通过单元测试、协议模拟测试和隔离 Pocket 的真实 API 集成测试；已验证真实微信扫码，以及 `/help`、`/status` 的收发。**真实微信上的普通模型任务全链路、媒体和长期主动通知尚未完整验证。** iLink 的开放范围和服务端限制可能变化；这不是腾讯或 Pi Pocket 的官方插件。

## 能做什么

- 微信 iLink 扫码登录、HTTP 长轮询；无需公网回调或浏览器自动化。
- 只接受扫码返回用户身份的私聊，且 Pocket 凭证必须属于 owner。
- PiP 默认入口；固定会话 ID 切换、新建会话。
- 一个微信私聊只绑定一个当前会话；切换后不再转发旧会话回复。
- 普通模型回复仅发送正文，不添加会话 ID/名称前缀；管理命令显示会话信息。
- 文字和图片/文件引用作为模型上下文，不用于切换路由；快速连续文字默认合并提交。
- `/stop`、`/model`、`/busy` 控制当前会话；工作中刷新微信输入中提示，失败不影响任务。
- 接收图片和文件并上传到 Pocket，`/send <项目内路径>` 显式发回图片或文件；不自动上传模型回复中的本机路径。
- Markdown 按段落和代码块分片；超长代码块会闭合并在下一片重新打开。
- 提醒在网页审批，不通过微信批准危险操作。
- SQLite 持久化收件、路由、回复游标和待发送消息；重启后恢复。
- 不传输模型思考和工具日志；不使用“相同正文”去重，重复发送“继续”仍有效。

仍**不支持群聊、语音识别（ASR）、语音合成（TTS）、原生语音/视频消息处理、消息编辑、多用户或多机器人实例**。iLink 登录获得的是独立机器人身份，不是对个人微信全部聊天的访问权。

## 要求

- Node.js **24+**，npm。
- 一个可访问的 Pi Pocket 服务，启用 PiP，并在网页选好默认模型。
- 自己的 Pocket owner 登录 token 和可使用 iLink 机器人的微信账号。
- 测试基线：Pi Pocket 0.13.2，commit `de612d5622cdc66b6b8b4900c650c6f2efdf4c63`；HTTP API 属于 Pocket 的内部接口，不保证其他版本兼容。

## 快速开始

```sh
git clone https://github.com/wangbinyq/pi-pocket-weixin.git
cd pi-pocket-weixin
npm ci
cp .env.example .env
chmod 600 .env
```

编辑本地 `.env`：

```dotenv
POCKET_URL=http://127.0.0.1:8080
POCKET_TOKEN=你自己的Pocket-owner-token
# 手机可打开的地址，只用于会话链接，不携带认证信息：
# POCKET_PUBLIC_URL=https://your-pocket.example.com
```

从你自己的 Pocket owner 登录链接取得 token；**不要把整个登录链接填进 POCKET_URL**。不要把 token 发进微信、提交到 Git 或放进截图。示例端口只是占位，以你的服务地址为准。

HTTP 只允许 loopback（localhost、127.0.0.1、127.0.0.2、::1）；远程 Pocket 必须使用 HTTPS。拒绝重定向，防止凭证发送到其他地址。

**返回链接的域名独立配置：** 设置 `POCKET_PUBLIC_URL=https://your-pocket.example.com`，所有命令和审批通知中的会话链接都会使用它；不设置则使用 `POCKET_URL`。它只改变给人的链接，不改变桥接连接 Pocket API 的地址，也不向该公网域名发送 owner token。仅接受 origin，不要附带登录 token、路径或查询参数。`doctor` 会显示当前返回链接地址。systemd 部署请修改服务使用的 `EnvironmentFile`，再重启桥接（无需重启 Pocket）。

```sh
npm run login    # 用本人微信扫码并确认；二维码也不要分享
npm run doctor   # 检查 Pocket owner 认证及本地配置；不验证微信登录有效性
npm start
```

在微信中给机器人发 `/help`，然后直接说话。首次启动会创建或打开已有 PiP，但不会自动给模型发送消息。扫码若没有返回用户标识，程序拒绝启动开放式机器人，不允许“第一位发消息的人自动成为 owner”。

按 Ctrl+C 停止。切勿让 Hermes、OpenClaw 或另一个服务同时轮询同一个 iLink 机器人。桥接会锁定自己的数据目录，并在同一系统用户下按机器人账号加锁；无法阻止其他软件或另一台机器抢用账号。

## 会话切换

| 命令                              | 行为                                                        |
| --------------------------------- | ----------------------------------------------------------- |
| `/pip`                            | 回到现有 PiP 管家                                           |
| `/sessions`                       | 列出最近 30 个会话，显示 Pocket 固定 ID                     |
| `/resume 12`                      | 恢复会话 #12，不是列表第 12 项                              |
| `/new 标题`                       | 新建会话并连接，目录和模型使用 Pocket 默认值                |
| `/reset [说明]`                   | 当前会话开启新上下文，保留历史；可附带交接说明              |
| `/stop`                           | 停止当前会话运行，撤回先前排队输入，不取消独立后台任务/计划 |
| `/model [provider/id] [思考级别]` | 列出已配置模型，或显式切换当前会话                          |
| `/busy [queue                     | steer                                                       | interrupt]` | 查看/设置并持久化忙时策略，默认 queue |
| `/send <项目内路径>`              | 显式发送当前项目的图片或文件，仅同机 Linux loopback 部署    |
| `/status`                         | 会话/路由、模型/上下文、队列、24h 窗口、桥接版本/重启时间   |
| `/retry-send`                     | 重试暂停的微信发送，不重新执行模型；可能重复送达            |
| `/help`                           | 查看帮助                                                    |

- **单当前会话：** 采用 Hermes 的核心路由方式。只有当前会话的新最终回复会转发；旧会话收到消息不会改变输入目标。首次连接或切回一个会话从历史末尾开始，不补发离开期间的回复。重复恢复当前会话不会丢弃已在同步的回复。
- 切换会在同一事务中改变目标、取消旧同步和所有尚未发出的旧会话回复，不停止 Pocket 的旧任务。已经发出的 HTTP 请求无法撤回，仍可能在切换后到达微信。
- 普通模型回复只发正文，不添加 `【#12 会话名称】` 前缀；会话列表、切换确认、状态和审批通知保留定位信息。
- **当前会话的全部新最终回复**仍可能包含网页和定时任务触发的输出；这是复用 Pocket 历史接口的桥接行为，不等同于 Hermes 的逐次 agent 回答和独立通知机制。
- 文字引用按 `[引用: 标题 | 原文]` 送给模型，不从引用内容推断会话，也不将引用中的斜杠命令当作桥接命令。引用中的图片/文件和普通附件一样下载并传入当前目标；语音、视频或不完整附件会拒绝整条请求，不忽略附件后执行。带附件的直接斜杠命令不执行，请单独发送命令。
- 连续普通文字默认等待 300ms 静默后合并，接近平台拆分长度的末段等待至少 1s；命令、媒体和超过间隔的输入不合并。合并结果先落盘，之后的重试不吸收新消息，使用首条的固定请求 ID。
- `/reset [交接说明]` 调用 Pocket 原生“新上下文”，保持当前会话 ID、模型、目录和历史记录，不新建会话、不停止任务、不取消计划或桥接待发回复。忙时在下一处理边界生效；交接说明最多 20000 字符，保留换行。接口无幂等键，超时或进程中断后不会自动重复执行，请检查网页中的新上下文标记。
- 网页当前选中的会话与微信绑定独立。每次提交前固定目标，重试不会误投到后来切换的会话。
- 普通输入走 Pocket 正常提交链路。`/busy queue`（默认）用 follow-up 排队，`/busy steer` 使用原生 steer，`/busy interrupt` 先停止再提交，不是原子操作；停止结果不确定时不会自动发送后续任务。`/stop` 可以越过先前普通待处理输入并撤回它们，但不跨越会话切换等命令边界；已经发出的提交无法撤回。
- `/model` 只列出已配置模型，不自动选择；`/model provider/id [思考级别]` 才修改当前会话。提供商登录、审批和计划批准仍在网页处理。`/stop`、模型切换与中断的意图先落盘；结果不确定时不会自动重复，避免停止新任务或覆盖后来设置。
- 旧的 `/use`、`/watching`、`/unwatch` 已移除。`/retry` 只说明未支持 Hermes 的重新回答语义，不转交模型，也不隐式重发。
- 升级时自动保留当前路由、同步游标和收发队列，停用旧的非当前订阅及待发回复。数据库升级至 v3（新增附件及上传结果字段），旧版代码不能直接打开；不要手工编辑数据。
- 将结果发往微信意味着相应内容离开 Pocket。只连接你愿意同步内容的会话。更完整的对照见 [Hermes 行为与边界](docs/hermes-parity.md)。

## 状态与公网链接

- `/status` 短暂读取 Pocket **已有** `GET /api/poll?c=<当前ID>` 的首帧 view，再 `close=1` 释放；使用桥接已有 owner Bearer token，不读取 Pocket 配置或数据库，不改 Pocket 源码。读取最多 4 秒，关闭最多 2 秒；关闭失败由 Pocket 60 秒到期清理。订阅会短暂出现为查看者，不提交模型任务。
- 显示当前 ID/标题/PiP、同步水位、当前模型、tokens/窗口/占比、待审批/忙闲、桥接入站/出站积压及 blocked/failed、最后入站、桥接版本与实例启动时间（UTC）。缺失显示 `unknown`。tokens 是 Pocket 最近有效响应的输入+输出+缓存用量；reset/压缩后的估算显示 `Pocket估算`，不是实时精确计数。
- 最近入站是去重后本人消息的**桥接接收时间**，持久化且重启保留；旧库从已有 received 恢复，没有记录就是 unknown。本次 `/status` 本身也刷新它；24h 的 OPEN/EXPIRED 只是该时间推导的窗口参考，不是微信确认可发送的保证，重复消息不刷新。
- `/status` 的诊断回执可越过暂停/退避的发送队列；它不重试、不取消、不改序普通回复，也不能绕过微信自身的会话窗口。队列计数是快照，不含本次诊断命令/回执。
- `POCKET_PUBLIC_URL` 仅用于文本链接，必须是无路径/查询/凭证的 origin；认证 API 仍只访问 `POCKET_URL`。所有出站文本（含普通模型回复、命令、帮助、审批、错误）在分片前统一处理，发出时再次处理已有队列。识别 API origin、同端口 loopback 别名、当前公网 origin、相对 `/s/ID` 与 protocol-relative 链接；不猜测其他域名。未配置时明确提示设置变量，绝不回退到 API 地址。
- 保留 URL 路径、entry/from/before/path/line/tab/sheet/download 查询定位参数和数字 entry 锚点；其他查询/锚点不转发，登录/邀请链接隐藏，URL 内的登录凭证移除。无关站点保持原文。不从任何链接自动下载或上传文件。

## 图片与文件

- 入站最多 8 个附件，每个最多 **20 MiB**；微信 CDN 限定 HTTPS allowlist，拒绝重定向，解密采用协议要求的 AES-128-ECB/PKCS#7，错误填充不容错。语音/视频消息一律拒绝，不使用微信语音转写文本。普通文件按附件透传，不做 ASR/TTS 或视频分析。
- 附件先经认证 API 上传到当前 Pocket 会话，再与文字使用同一个幂等 requestId 提交。每个已取得的上传结果都会保存；部分下载失败时不提交残缺文字任务。Pocket 上传接口没有幂等键，响应丢失可能留下未引用上传文件，但不会因此重复执行模型任务。图片是否进入视觉上下文由 Pocket 的模型能力、格式及大小限制决定（当前最多内联 5 MiB）；不保证任意文件都能被模型理解。
- `/send path/to/report.pdf` 只读取明确指定的当前项目文件；有空格的路径直接写在命令后，不需要引号。不从模型回复的 Markdown、MEDIA 标记或 URL 自动读取文件。图片按文件签名识别，其他内容按文件发送，不取远程 URL。
- `/send` 仅限 Linux、同主机共享文件系统且 `POCKET_URL` 为 loopback 的部署；容器/SSH 端口转发并不保证共享文件系统，请勿用于这种部署。PiP 不直接导出，请先 `/resume <项目会话 ID>`。目录外路径、越界符号链接、特殊文件、桥接状态目录以及常见凭证/数据库文件均拒绝。此过滤不是内容级防泄漏扫描，仍须自己确认导出的文件可公开给微信。
- 发件保存不可变文件快照与 CDN 上传结果，重试复用它们和稳定 client_id；切换会取消旧会话未发附件。缓存私有且不加密，启动时清理超过 7 天且不再被待发队列引用的快照；不会清理 Pocket 管理的上传文件。
- `/send` 的确认文字排在它自己的媒体**之后**：媒体行要等 CDN 上传（最长 120s）才能发出，文字行可以立刻发出，先发文字会把图片和它的说明在时间上拉开，`/status` 诊断回执也能越队插进两者之间。代价是上传期间没有回执，上传最终失败时回执按队首阻塞语义一起等 `/retry-send` 或 `/status` 处理。
- 输入中提示尽力发送：Working 期间约每 2 秒心跳重发，等待审批、空闲、切换和退出时关闭；入站时预取 typing ticket，未获得 ticket 或接口失败只记一行状态日志，不阻止任务。

## 配置与数据

可选环境变量：

| 变量                         | 默认 / 含义                                              |
| ---------------------------- | -------------------------------------------------------- |
| `WEIXIN_DATA_DIR`            | `~/.local/share/pi-pocket-weixin`；独立私有数据目录      |
| `POCKET_PUBLIC_URL`          | 无默认值；手机可访问的 Pocket origin，未配置明确隐藏链接 |
| `POCKET_NEW_CWD`             | /new 使用的工作目录；不填则由 Pocket 决定                |
| `WEIXIN_TEXT_BATCH_DELAY_MS` | 300；0 关闭合并，最大 2000 毫秒                          |

程序从当前工作目录读取 .env。不要把数据目录放在仓库里。目录权限 0700，凭证和 SQLite 主文件权限 0600；首版主要面向 Linux/macOS，未验证 Windows 的权限与文件系统行为。

数据目录内：

- `credentials.json`：机器人 token、API 地址和绑定的微信身份。
- `bridge.sqlite`（及 WAL/SHM）：待处理消息、附件引用与媒体密钥、context_token、轮询游标、当前目标和同步游标、忙时策略、待发回复与 CDN 上传结果、去重键。
- `media/`：待发附件的内容寻址私有快照，文件 0600，目录 0700。

**这三个概念不同：** bot token 是接口凭证；context_token 是某个微信联系人的回复令牌；Pocket conversationId 才是 AI 会话。

首次启动将数据绑定到 Pocket URL + owner ID + 机器人账号 + 微信身份。改变这些身份会拒绝使用旧状态；新账号或其他 Pocket 实例请用新数据目录。仅轮换同一身份的凭证不需要清空状态。更换同一个 Pocket 服务的 URL 也需要单独规划迁移，当前没有迁移命令。

已完成的收件正文/附件引用和已发送的回复正文/媒体密钥会清空，但去重键仍保留。待处理内容属于敏感信息；日志不打印聊天正文、token、模型输出或原始 API 错误体。不要在公开 issue 上传 .env、数据目录或二维码。

## 恢复语义与限制

1. **接收：** 合法消息、最新回复令牌、iLink 游标在同一 SQLite 事务落盘；进程重启后先处理已保存收件。仅处理有稳定 message_id 且身份匹配的受支持私聊；线上的 64 位数值 ID 按原始数字精确保留，避免 JavaScript 数值精度损失。轮询收到 -14 或特定会话失效 -2 时暂停 10 分钟；一般错误按 2s、2s、30s 退避。
2. **Pocket 提交：** 请求 ID 由机器人、发送者和微信消息 ID 派生，固定为 64 位十六进制。响应丢失后重用它，利用 Pocket 的提交去重，避免重复执行同一条输入。
3. **新建会话：** Pocket 的新建接口没有幂等键，因此在发送前记录意图。响应丢失或进程在记录结果前中断时，**不会自动再创建**，而是提示 /sessions 检查；有可能留下一个已创建但尚未连接的空会话。
4. **回复：** 历史分页补齐，回复入 outbox 与读取游标在同一事务提交。使用稳定 client_id 重试，每个分片约 1800 Unicode 码点，发送至少相隔 1.5 秒。
5. **不是端到端 exactly-once：** 微信接受消息后若 HTTP 响应丢失，或进程在记录已发之前退出，重试可能重复。iLink 服务端的 client_id 去重行为尚未实测，不能保证绝不重复。
6. **主动通知有条件：** context_token 失效时尝试一次移除旧令牌发送；仍失败会暂停队列，等待你再次发消息或重新登录。不能保证长期无人交互后仍可主动推送。
7. **发送顺序：** outbox 按顺序处理，遇到暂时错误退避；连续失败最多尝试 8 次，然后暂停，避免无限刷屏。队首暂停会阻塞后面的消息，也会挡住它后面的确认文字。媒体行排在自己的确认文字之前，避免上传耗时把图和说明拉开（见「图片与文件」）。用 /retry-send，或停止服务后运行 `node src/cli.ts retry-send` 恢复。网络不确定的重试可能重复。
8. **本地存储：** SQLite FULL 同步与原子凭证替换防止常见进程中断问题，但不能承诺损坏磁盘或网络盘上的可靠性。使用本地文件系统。去重记录没有自动过期，长期运行要留意磁盘空间。

代码结构：

- `src/ilink.ts`：扫码与 iLink 文本/媒体/typing 协议、私聊身份过滤。
- `src/media.ts`、`src/weixin-media.ts`：媒体限制、私有快照、安全文件导出、CDN allowlist 与协议加解密。
- `src/pocket.ts`：Pocket 鉴权 API、历史分页和最终回复筛选。
- `src/store.ts`：SQLite 收件箱、发件箱、单会话路由和持久化文字合并。
- `src/bridge.ts`：命令、输入路由、回报和重试。
- `src/cli.ts`：登录、检查、进程生命周期与锁。
